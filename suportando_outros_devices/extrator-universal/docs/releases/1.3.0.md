# NXExtract 1.3.0

NXExtract 1.3.0 closes `V3-HARDENING-01` for recipe hooks and closes the last
`APK-COMPAT-01` gap with a real legal fixture.

## The resource fence around a recipe hook fails closed

Up to 1.2.21 the fence swallowed every error while establishing
`RLIMIT_CPU`, `RLIMIT_AS`, `RLIMIT_FSIZE` and `RLIMIT_NPROC`. A host where a
limit could not be applied therefore ran the hook with **no ceiling at all** —
precisely the state those limits exist to prevent, and precisely the case where
a runaway hook does the most damage.

The fence now refuses. A limit that cannot be read, lowered or confirmed raises
inside the child before `exec`, so the hook never starts unfenced and the
engine reports `cannot start hook <id>`. The regression carries a positive
control: the same recipe runs the hook normally without the injected failure,
so the negative cannot pass vacuously.

Nothing about the fence applies to the game process; it never did and still
does not. The limits, their ceilings, the wall clock, the line budget and the
total output budget are unchanged.

## APK compatibility is now proven against a real legal copy

Every previous compatibility test used synthetic blobs. A synthetic fixture is
built to match, so it cannot catch the failure that opened this front: a
published artifact rejecting the very data its own documentation declared
compatible.

The new framework gate runs the **generated pipeline itself** — not isolated
functions — against an owner-supplied legal copy, and proves the property the
contract actually claims: **the identity of the container never decides
compatibility**. The same bytes are presented under a different file name,
repacked with a reversed member order, a different compression method,
far-future timestamps, DOS attributes and foreign extra fields, and in another
supported container format. All of them must resolve exactly the same payload
set. The negatives are another game's package, a missing required payload — the
refusal naming the technical property — and an ABI the recipe never declared.

Nothing is discovered: both the container and the recipe are supplied
explicitly, and an absent fixture is reported as a stated limit of claim, never
as a pass. The proprietary artifact never enters the repository, and the stored
receipts carry only technical identity: recipe, ABI, payload count, total bytes
and the reference copy's size and SHA-256.

## Compatibility

The runner and the runtime environment helper are byte-identical to 1.2.21. The
presentation is unchanged: the graphical SDL2 UI, the fbdev renderer, the
640x480 and 1280x720 pixel goldens, the terminal-result schema and the four
immutable low-glibc UI binaries are the same artifacts.

Markers written by 1.2.21 and 1.2.20 remain compatible. No published port is
migrated: it stays valid on the engine it ships, and the outgoing 1.2.21
identity is registered in the engine identity ledger at the moment of this bump.
