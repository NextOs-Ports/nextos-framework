# NXExtract 1.2.6

Compatibility fix. Case-insensitive ZIP path safety is now enforced over the
members a recipe actually selects instead of over the whole archive.

## Why

Real Android APKs routinely carry obfuscated resources whose names differ only
in case — Swordigo 1.4.12 ships `res/9N.9.png` next to `res/9n.9.png`. Until
1.2.5 that alone made NXExtract refuse the archive, even when the recipe only
extracted `assets/**`, `res/*.mp3` and one native library, none of which
collide. A legitimate, correctly owned APK was rejected with a message about
files the port never writes.

## What changed

- `Archive` records case collisions found while opening an archive instead of
  raising immediately;
- the selection stage rejects a collision only when two **selected** members
  collapse to the same portable path, per archive;
- the guarantee is unchanged for what lands on the card: an extracted tree is
  still writable on a case-insensitive filesystem (exFAT/FAT), because the
  check now covers exactly the set of paths that gets written.

Duplicate exact entries, file/directory collisions, encrypted members and
linked or special members remain fatal at open time.

## Compatibility

No recipe change is required. A recipe that used to fail on a colliding
archive now installs, and a recipe that selects genuinely colliding members
still fails, with the same message and exit status as before.
