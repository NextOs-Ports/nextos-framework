# NXExtract 1.2.7

NXExtract 1.2.7 closes the silent/headless setup gap exposed by a physical
dArkOSRE-family test. The packaged UI was present and started, and SDL advertised
KMSDRM, but window creation could not load an EGL/GLES provider. Older UI bytes
retried and then exited successfully, allowing a long extraction with no visible
progress.

The new AArch64 UI preserves the normal order: inherited/default SDL first, then
each capability-plausible backend advertised by the same SDL build. When none can
create a real window, it opens only the active virtual terminal published by
`/sys/class/tty/tty0/active` and draws bilingual dynamic progress there. It does
not select a game graphics provider, load private game libraries, inspect a
firmware name or alter the later native lifecycle.

The packaged `run-extractor.sh` now passes `--require-ui`. The UI publishes a
private `ui.ready` proof only after the SDL renderer or active TTY is open; the
Python parent waits for that proof and fails before package scanning or payload
mutation if it never arrives. Direct developer invocations of `nxextract.py` may
still omit this flag for headless automation, but generated/public ports do not
have an opt-out.

Physical UI-path evidence on AArch64 confirmed:

- real KMSDRM window failure due to unavailable EGL/GL;
- fallback to the kernel-published active `tty1`;
- `visible=tty` readiness before extraction work;
- an inspected 80×30 console buffer containing the game, recipe, phase, current
  file, phase/overall bars, English/Portuguese status and RETRO ELITE footer.

This is UI-path evidence, not yet a claim that every device family completed a
full 1.2.7 owner-data release. Exact port ZIPs retain their own physical
acceptance gate.

The canonical UI SHA-256 is
`b4daf1bdffe4f1623752742bc6b796f93a203f8e4cba4c39f62dfcfd37cc2d72`.
It requires at most `GLIBC_2.17`, has the canonical AArch64 interpreter, and
imports only `libc.so.6` and `libdl.so.2`.
