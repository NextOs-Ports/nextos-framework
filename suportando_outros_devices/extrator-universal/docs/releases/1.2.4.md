# NXExtract 1.2.4

Feature release. Recipes can bind legal input to the expected Android package
and can install a selected APK as one complete payload file.

## Changes

- adds `input.packages`, a list of accepted Android application IDs;
- rejects a known package belonging to another game with a diagnostic naming
  both the package supplied and the package expected by the port;
- keeps an APK with unreadable package metadata eligible, so strict payload
  validation remains authoritative rather than treating missing metadata as a
  false rejection;
- adds source kind `container`, which copies the selected APK itself instead of
  extracting its members;
- makes `container` select the base APK by default, allows a named `split`, and
  excludes an outer APKM/APKS/XAPK bundle from the candidate scope.

Sibling games built by the same studio can share engine layout, asset paths and
even validation sizes. Content rules alone could therefore accept the wrong
application silently. Package binding rejects that mistake early without
weakening validation for packages whose manifest cannot be decoded.

Some engines open their APK with minizip at run time. Rebuilding that package
from an extracted tree costs temporary space, can change compression semantics
and leaves an unnecessary second copy in the committed payload. `container`
provides the exact package selected from a loose APK or bundle, ready for an
optional stage-only normalization hook.

The Python core still supports Python 3.7 or newer. The bundled AArch64 UI is
unchanged and requires only GLIBC 2.17. No proprietary game data is included.
