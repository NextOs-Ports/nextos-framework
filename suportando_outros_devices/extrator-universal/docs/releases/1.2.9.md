# NXExtract 1.2.9

NXExtract 1.2.9 is an additive graphical-readiness correction on top of the
immutable 1.2.8 interface. It does not change `draw_screen()`, its layout,
palette, typography, progress bars or the extraction/payload model. The
640x480 and 1280x720 pixel goldens remain exact.

## Portable provider recovery

An ArkOS full-launcher run showed SDL KMSDRM failing 30 bounded window attempts
with `Can't load EGL/GL library`, then opening the approved graphical fbdev
renderer only near the old 20-second engine deadline. On the same device,
NXSplash 0.1.2 had already recovered KMSDRM immediately by retrying the
unversioned `libEGL.so` and `libGLESv2.so` provider names.

Version 1.2.9 reuses that approved NXSplash recovery contract. NXExtract first
honors the normal inherited/default SDL selection. Only after a real window
failure, and only when neither `SDL_VIDEO_EGL_DRIVER` nor
`SDL_VIDEO_GL_DRIVER` was explicitly supplied, it tries the portable names.
If that attempt fails, the temporary variables are removed and the proven
six-retry-per-backend negotiation continues unchanged. Graphical fbdev remains
the final approved fallback. No device name chooses a backend or provider.

The host gate supplies a fake SDL whose window opens only with those portable
names, and separately proves that an explicit provider pair is never replaced.
The exact 1.2.9 AArch64 UI was also exercised in two isolated physical probes.
NextOS Amlogic-old / Mali-450 opened the approved SDL layout with the `mali`
driver, returned `visible=sdl`, and a valid graphical capture was inspected.
The authorized ArkOS-class AArch64 / KMSDRM target returned `visible=sdl` after
portable EGL/GLES recovery and its log identified KMSDRM, but has no valid
visual capture: `/dev/fb0` retained an older frame while DRM owned scanout.
Both probes left no UI process after shutdown. These are component-only
renderer receipts, not claims that a new game ZIP passed installation or
full-game validation; the KMSDRM result is not visual-layout proof.

## Forty-second fail-closed boundary

The engine now waits at most 40 seconds for an exact private
`visible=sdl` or `visible=fbdev` proof. A deterministic time simulation proves
that a renderer appearing at 20.5 seconds is accepted and that absence through
40 seconds still raises an error before package discovery or owner-data
mutation. TTY, malformed, unsafe and exited-renderer proofs remain rejected.

The longer boundary is only tolerance for a slow approved graphical path. It
does not permit headless extraction, change retry counts or add an opt-out.

## Private runtime control plane on FAT/exFAT

A physical ArkOS run exposed a separate boundary bug: `/roms` uses FAT/exFAT
permission semantics and reported the game workspace as `0777`. NXExtract was
correct to reject a `0777` readiness proof, but 1.2.9 still placed that proof
under `.nxextract`, where a private POSIX mode cannot be represented reliably.

The readiness protocol is now additive and filesystem-correct. Every UI run
creates a unique `0700` directory under a safe owner-private
`XDG_RUNTIME_DIR`, or under a trusted sticky/private `TMPDIR`/`/tmp` fallback.
The engine checks the directory owner, mode and inode without following links;
`ui.ready` and `ui.stop` remain inside that directory and the session cleanup
removes them. The diagnostic, non-authoritative `ui.log` and persistent
transaction state remain in the game tree. No `0777` readiness file or
directory is accepted.

A synthetic chmod-insensitive game-tree fixture forces an in-tree proof to
`0777`, so the install succeeds only when the UI receives paths in the private
runtime. A second fixture supplies a linked `XDG_RUNTIME_DIR` and a non-sticky
`0777` `TMPDIR`, proving the independent `/tmp` fallback. An all-unsafe fixture
proves the helper fails closed instead of returning an unsafe control directory.
No UI drawing code or release ELF changed.

## Preserved data contract

Package selection remains content-driven. External APK/APKM/APKS/XAPK names,
container signatures and whole-container hashes do not identify the game.
Recipes continue to validate package ID, version contract, ABI, structure and
critical internal payload identity, accepting legitimate repackaging while
rejecting a wrong game, ABI or internally incompatible build.

This is enforced at recipe load for `container` sources without invalidating
published ports. `input.packages` is required; exactly one whole-container
SHA-256, one CRC32 or one exact size is forbidden. A hash-free container can be
qualified by package plus internal payload, tree and/or hook validation; a list
of two or more distinct explicitly supported official container identities
also remains valid. Regressions preserve the Angry Birds, ScourgeBringer and
Retro Highway recipe shapes. A synthetic gate additionally installs two
containers with different whole hashes but the same compatible content, then
proves that a wrong package and a changed internal ELF remain rejected without
replacing the live payload.

## Self-contained source archive

The exact bundle-pin helper now lives inside the component's `tools/` tree.
Consequently an exported standalone source archive can run
`tools/check-release.sh --require-ui` in isolation; it no longer relies on a
sibling helper from the private parent monorepo. This packaging correction does
not change the extractor engine or any graphical UI artifact.
