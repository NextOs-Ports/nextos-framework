# NXExtract 1.2.19

NXExtract 1.2.19 implements APK-COMPAT-01 of the V3 wave: compatibility of the
owner-provided container is decided ONLY by runtime contracts, never by the
identity of the tested copy. The setup screen pixels, the separately pinned
immutable 1.2.16 UI, the terminal-result schema and the NXE#### format are
unchanged.

## Why

The Terraria 2.0.0 regression (2026-08-26) proved that identity leaks into
compatibility in two ways: a whitelist of container SHA-256 values (1.2.18
rejected a single digest but accepted lists of two or more), and custom hooks
that grep a literal version token inside an asset (the documented `1.4.5.6.4`
against the real `1.4.5.6.49`). Both rejected data the port's own
documentation declared compatible.

## What changed

- New canonical module `framework/contracts/apkcompat/apkcompat.py` embedded
  verbatim (sync-gated byte identity) — the single implementation of the
  container-compatibility rule shared with NXGenerator and NXRelease.
- Container rules refuse `sha256`/`crc32` in ANY quantity and exact `size`
  (codes NXA0001..NXA0003). Bounded size, magic and `elf_machine` remain the
  structural contract. `input.packages` stays mandatory for containers.
- New optional documentation-and-decision separation in the recipe:
  `reference_build` (identity of the tested copy, documentation only),
  `compatibility` (package families, ABIs, required members, payload
  contracts — cross-checked against `input.packages`/`abi_order`) and
  `patch_profiles` (internal-payload hash may select a patch; a mandatory
  `fallback` keeps unknown compatible builds on the generic path).
- Hooks may declare an inline `contract` (org.nextos.apk-compat.hook-contract
  v1) naming inputs, predicates by class
  (`reference_identity`/`compatibility`/`patch_selection`), patches, fallback
  and stable error codes. A contract whose predicates are only
  `reference_identity` is refused at recipe load (NXA0046).
- Hook runtime protocol: `NXEXTRACT_PREDICATE <class> <name> <ok|fail>` lines
  are collected; a hook that fails using only reference_identity predicates
  is reported as the contract violation it is, and failed compatibility
  predicates are named in the terminal error.
- Static defence `scan_static_suspects` flags 64-hex equality, literal dotted
  version tokens, size tables and absolute offsets in custom logic
  (NXA0050..NXA0053) for the generator/release gates.
- Observability (V3-OBS-01): when the launcher provides `NXOBS_RUN_ID` and
  `NXOBS_EVENTS_FILE`, the engine appends `nx-event-v1` JSON lines
  (begin/ok/failed) to the shared `events.jsonl`. Purely additive and best
  effort; no UI or flow change.
- V3-HARDENING-01: hook resource fence (group kill, rlimits, wall timeout,
  output caps, `hook.limits` bounded overrides) and a 1 MiB recipe parse
  ceiling; the stage is preserved on every violation.
- Terraria regression pinned: documented `.4` with internal `.49` installs
  green from a renamed container while every negative stays strict.

## Compatibility

Published ports keep their vendored engines. Recipes that never locked the
container by hash need no change; a recipe carrying a container SHA whitelist
must move those digests to `reference_build` (documentation) before adopting
1.2.19. Suite: 89 cases.
