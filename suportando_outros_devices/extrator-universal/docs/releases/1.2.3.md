# NXExtract 1.2.3

Patch release. A ZIP-format OBB can now be selected as the payload file itself
without losing the ability to inspect entries inside it.

## Changes

- keeps a loose `.obb` classified as a generic ZIP archive available in the
  loose-file candidate set as well;
- lets `file` and `entry_or_file` rules select that complete OBB by content,
  size, hash or magic rather than by its external filename;
- leaves `entry` rules unchanged, so recipes can still extract members from the
  same OBB when that is what the Android game does;
- preserves the legal source file throughout discovery and installation.

Many publishers, including Aspyr, Gameloft and Rockstar, ship OBB files that
are ordinary ZIP archives. Earlier releases classified such a file only as an
archive. A recipe asking for the whole OBB therefore searched *inside* it and
reported the required loose payload missing. KOTOR build 53 exposed the issue:
its own `ObbFile` layer consumes both OBBs whole, so unpacking their members is
not equivalent.

The Python core still supports Python 3.7 or newer. The bundled AArch64 UI is
unchanged and requires only GLIBC 2.17. No proprietary game data is included.
