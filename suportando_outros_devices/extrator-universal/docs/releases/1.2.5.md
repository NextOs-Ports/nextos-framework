# NXExtract 1.2.5

Hardening release. NXExtract now has a fully audited publication transaction,
strict marker identity, hostile-filesystem defenses and exact whole-kit pinning
for new or touched PortMaster ports.

## Durable publication and recovery

- transaction journal format 2 records write-ahead intent before every backup
  and install rename, then records the confirmed state afterward;
- every transaction rename fsyncs both affected parent directories;
- fourteen simulated power-loss boundaries cover journal creation, backup
  skipped/intent/rename/record, install intent/rename/record, full validation,
  marker publication and journal publication;
- before marker publication, recovery restores the complete previous live
  payload and preserves resumable staged work;
- after marker publication, recovery retains the complete new payload only
  after a full validation and metadata-seal check; corrupt publication rolls
  back;
- the marker binds exact NXExtract version, recipe ID/version/digest, ABI,
  expanded commit roots, plan fingerprint, transaction ID, selected items and
  every committed object's type/path/size/mtime seal.

The marker is the publication boundary. Backup, stage, source-cache and journal
removal after that point is best-effort housekeeping. A FUSE, SMB, NFS, FAT or
exFAT cleanup refusal cannot turn an installed and validated game into exit 1;
the retained journal makes cleanup safely retryable on the next launch.

## Hostile input and filesystem handling

- recipes fail before log/workspace effects when templates are unknown, paths
  overlap the private workspace/marker/log, or the recipe is linked (including
  through an intermediate linked parent);
- private logs, locks, progress, markers, journals, cache, stage and hook state
  reject symlinks and hardlinks;
- ZIP traversal, encrypted/special members, file-versus-directory conflicts and
  Unicode/case-fold collisions are rejected globally, even when the recipe
  would not select the hostile member;
- staged and published payloads reject nested symlinks, hardlinks, special
  files and non-portable path collisions;
- bundle free-space accounting counts exactly the valid cached inner APKs that
  are still missing; stale/extraneous cache entries cannot suppress preflight.

APK, APKM, APKS, XAPK, ZIP and OBB files remain bring-your-own legal sources.
They are never deleted or redistributed. All 55 Python regressions synthesize
their own tiny fixtures at test time.

## Runtime, package and UI gates

- `run-extractor.sh` invokes the runtime helper explicitly through `bash`, so
  loss of executable mode bits on FAT/exFAT does not bypass isolation;
- the child-only environment removes game-private paths through lexical and
  canonical boundaries, preserves inherited SDL backends by default, and never
  chooses video/audio providers itself;
- a new/touched port must vendor the exact 1.2.5 engine, runner and helper;
  SHA-256 comparison rejects mixed bundles, while 1.2.2 is only the historical
  audit floor;
- every release member must be regular, nonempty and non-symlink; all detected
  ELFs pass the low-glibc gate;
- the unchanged AArch64 UI is PIE, RELRO/NOW, has a non-executable stack, no
  RPATH/RUNPATH, depends only on `libc.so.6` and `libdl.so.2`, dynamically loads
  firmware SDL2 and requires GLIBC 2.17;
- accelerated SDL rendering is tried first, software rendering second;
  invisible drivers are rejected and UI failure remains nonfatal/headless.

The UI binary is byte-identical to the release 1.1.0 asset whose visible
`mali`/fbdev and KMSDRM captures were physically verified. This does not claim a
new physical 1.2.5 device run; that remains a separate release gate.

The Python core retains Python 3.7 syntax and standard-library-only operation.
No proprietary game data is included.
