# NXExtract 1.2.1

Patch release. A committed, validated payload is no longer reported as a failed
install because the scratch source cache could not be deleted.

## Changes

- closes every source archive before the source cache is removed, so no file is
  unlinked while a handle is still open;
- routes the source-cache cleanup through `discard_path()`, which retries the
  removal, logs `warning: kept source cache for the next run` when the
  filesystem still refuses, and returns success either way;
- keeps every other transactional path strict: staging, validation, commit,
  rollback and the post-install data gate are unchanged;
- adds a regression test covering an install whose source-cache removal fails.

FUSE-backed shares replace a file that is unlinked while still open with a
hidden placeholder (`.fuse_hidden*`, `.nfs*`), so the parent directory answers
`ENOTEMPTY` even after every real entry is gone. On exFAT `/userdata` — the
layout Knulli and Batocera use — `source-cache/bundle-*` therefore returned
`[Errno 39] Directory not empty` immediately after the payload had been
committed and validated, and the generic `OSError` handler turned that into
exit 1. Ports report the failure to the user as a broken data setup even though
the game is fully installed. Local filesystems such as ext4 allow unlinking an
open file, which is why the defect stayed invisible until a report from a
firmware with an exFAT data partition.

Scratch space that survives one extra run is harmless; a good install reported
as a failure is not.

The Python core still supports Python 3.7 or newer. The bundled AArch64 UI is
unchanged and requires only GLIBC 2.17. No proprietary game data is included.
