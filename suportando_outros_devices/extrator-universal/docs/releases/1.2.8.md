# NXExtract 1.2.8

NXExtract 1.2.8 is an additive visual-regression recovery. It retains the
1.2.7 extraction engine, transaction journal, flexible package discovery,
whole-kit pinning and mandatory readiness boundary. It does not roll the engine
back to 1.2.6.

The graphical SDL interface approved from 1.1.0 through 1.2.6 remains the
visual baseline. Version 1.2.8 restores its six retries per advertised backend,
six attempts before abandoning an inherited backend and 500 ms retry interval.
If SDL itself loads but the firmware cannot create an EGL/GLES window, the same
`draw_screen()` implementation can render through a software surface mapped to
the active framebuffer. Drivers that reject `mmap` use bounded row-safe
writeback of that same software frame. This keeps the panel, palette,
typography and progress bars identical instead of substituting an ASCII box.

The engine now accepts only these exact private readiness proofs:

- `visible=sdl`, after the first SDL graphical frame is presented;
- `visible=fbdev`, after the first direct-framebuffer graphical frame is
  presented.

The 1.2.7 TTY renderer remains available only for explicit laboratory
diagnostics through `NXEXTRACT_ALLOW_TTY_UI=1`. A public runner still uses
`--require-ui`, and `visible=tty` is deliberately rejected before package
discovery or owner-data mutation. The bounded graphical readiness deadline is
20 seconds, enough for the restored retry budget.

The release now carries architecture-matched AArch64, ARMv7, x86_64 and i386
PIE artifacts with RELRO/NOW, no RPATH/RUNPATH, only `libc.so.6` and
`libdl.so.2` dependencies, and a maximum GLIBC requirement of 2.17. Exact
hashes, sizes and modes are fixed by `ui/release/manifest-v1.json`; a port must
vendor only the artifact selected for its declared architecture.

Physical game-package claims remain the responsibility of each exact port ZIP.
The same ZIP must visibly pass NXExtract, the post-extraction splash, native
game boot and clean exit before publication.
