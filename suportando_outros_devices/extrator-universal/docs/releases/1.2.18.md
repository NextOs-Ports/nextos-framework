# NXExtract 1.2.18

NXExtract 1.2.18 closes the redaction gap in the human-facing error sinks and
improves the most common BYO-data error message. Behaviour is otherwise
byte-identical: setup screen pixels, the separately pinned immutable 1.2.16
UI, the terminal-result schema and the NXE#### format are unchanged.

## Why

Only the terminal-result JSON passed through `sanitize_terminal_message`. An
unexpected `OSError`/`RuntimeError` printed the raw exception on the setup
screen and in the summary log — exactly the file a player pastes on a public
channel — leaking the host path and the owner's container filename. And the
most frequent community failure ("no APK ... was found") never said where to
put the file.

## What changed

- `progress.fail` and the `TERMINAL ERROR` summary line route the exception
  through the same redaction filter as the JSON (URLs, host paths and
  container filenames replaced by placeholders).
- The no-container error names the `gamedata/` folder, says to create it when
  missing, and lists the accepted extensions.
- Two new regression tests pin both behaviours (suite: 79 cases).

## Compatibility

Published ports keep their vendored engines (registry: 1.2.14–1.2.17 remain
supported). New packages vendor 1.2.18. No recipe change is required.
