# NXExtract 1.2.14

NXExtract 1.2.14 separates one support code by cause and changes nothing else:
the setup screen, its pixels, the terminal-result schema and the immutable
1.2.9 UI bytes are unchanged.

## I/O codes by cause (P13)

`NXE6001` covered every `OSError`, so a full card, a read-only mount, a missing
path and removed media all reached support as the same number. The failure that
matters most in the field was indistinguishable from the one that does not.

The historical code now splits by `errno`:

| Code | Cause |
|---|---|
| `NXE6002` | no space left / quota / file too large (`ENOSPC`, `EDQUOT`, `EFBIG`) |
| `NXE6003` | permission denied or read-only filesystem (`EACCES`, `EPERM`, `EROFS`) |
| `NXE6004` | path missing or not a directory (`ENOENT`, `ENOTDIR`, `ENAMETOOLONG`) |
| `NXE6005` | removed media or hard I/O error (`EIO`, `ENODEV`, `ENXIO`, `ESTALE`) |
| `NXE6001` | any other `OSError`, exactly as before |

Nothing about the screen changes: the code occupies the same slot, keeps the
`NXE####` shape that published launchers already validate by format, and no new
outcome category is introduced. Every other code family (`NXE1001`, `NXE2001`,
`NXE2002`, `NXE3001`, `NXE4001`, `NXE5001`, `NXE5002`, `NXE7001`, `NXE9001`)
is untouched.
