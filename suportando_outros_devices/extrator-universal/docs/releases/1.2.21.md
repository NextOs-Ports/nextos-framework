# NXExtract 1.2.21

NXExtract 1.2.21 prevents a metadata-only change on FAT, exFAT or FUSE from
silently turning an already valid multi-gigabyte installation into a new
extraction.

The ordinary launch remains cheap: the existing path/type/size/mtime seal is
checked first. A newly published marker also contains a stable SHA-256 over
every immutable path, object kind, size and byte. Only when the cheap seal
drifts does the engine read and compare that stable content seal. Matching
bytes reseal the marker atomically; mismatching bytes fail closed, including a
same-size modification.

The immediately preceding 1.2.20 marker can be migrated after the recipe's full
declared validation. The engine records the predecessor, preserves the original
transaction identity and never copies payload data during migration. Older
marker versions remain unsupported. If the legacy marker's metadata seal also
drifted, migration additionally requires an independently supplied exact
`--expected-content-seal`; it never blesses newly observed bytes by itself.

`install --reuse-only` (or `NXEXTRACT_REUSE_ONLY=1` through the packaged runner)
is the update/test guard: it succeeds only for authenticated existing data. If
that cannot be proven, it publishes a terminal error before starting the setup
UI, scanning owner containers or extracting a byte. It also refuses a pending
payload transaction instead of invoking recovery implicitly; no rollback,
roll-forward or stage publication is authorized by this mode.

This release does not change the NXExtract presentation. The graphical SDL2 UI,
fbdev renderer, 640x480 and 1280x720 pixel goldens, terminal-result schema and
four immutable low-glibc UI binaries are unchanged. A real installation still
requires the approved visible graphical renderer when the launcher passes the
existing `--require-ui` gate.
