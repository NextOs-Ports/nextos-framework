# NXExtract 1.2.16

NXExtract 1.2.16 moves the private UI session off the filesystem and onto
inherited descriptors, and changes nothing else: the setup screen, its pixels,
the terminal-result schema and the headless-fallback semantics are unchanged.
The UI binary is rebuilt for the new handshake and keeps accepting the
historical absolute-path contract, so its release identity moves to 1.2.16
while the on-screen identity stays byte-identical in the goldens.

## Why

A clean, long installation measured in the field (Brotato) reached the end of
the copy and still died with `NXE7001: UI runtime directory identity was
lost`. The cause was infrastructure, not data: on that firmware the login
session has `Linger=no`, so systemd recycles `/run/user/<uid>` the moment the
session ends — and the engine kept the UI handshake (`ui.ready`/`ui.stop`)
inside a `0700` directory under that `XDG_RUNTIME_DIR`. The second run resumed
the validated stage and finished with `NXE0000`, proving recipe, data and
loader innocent.

The pathname design also could not move to the game card: FAT, exFAT and some
FUSE mounts report `0777` regardless of `chmod`, so a private-mode proof under
`/roms` means nothing there.

## What changed

- The engine opens two pipes in the parent, before the UI spawn, and validates
  every descriptor with `fstat`: FIFO type, effective owner, private mode and
  exact dev/inode identity, failing closed on any divergence.
- The UI receives only inherited descriptors, as `fd:N` tokens in the
  historical `stop`/`ready` argv slots. The readiness proof — the same
  `visible=sdl` / `visible=fbdev` bytes — is sealed by the UI closing its
  write end. The stop request is a byte plus EOF, so an engine crash ends the
  UI instead of orphaning it.
- Every later use revalidates the descriptor identity; a substituted
  descriptor (another object dup2-ed onto the same number) is refused.
- No `ui.ready`/`ui.stop` pathname exists anywhere anymore. Removing any
  directory mid-extraction — the exported `XDG_RUNTIME_DIR` included, which
  stays untouched for Wayland — cannot invalidate a data transaction that
  already validated.
- A genuine handshake violation still maps to `NXE7001`; the code did not get
  reclassified.

## Proof

- A long-extraction fixture publishes the visible proof, waits for the copy
  phase and deletes the session directory exactly like the recycler does; the
  installation must finish `NXE0000` with the UI reaped and zero residue.
  Against 1.2.15 the same scenario reproduces the field failure.
- Negative fixtures cover a non-FIFO descriptor, a foreign-owned descriptor, a
  group-readable mode, a substituted descriptor and idempotent cleanup.
- Chmod-insensitive resilience: a `0777` game tree, a symlinked `0777`
  `XDG_RUNTIME_DIR` and a sticky-less `TMPDIR` all complete visibly, with both
  adversarial directories provably empty afterwards.
- The visual-identity gate holds: `draw_screen` untouched and the 640×480 /
  1280×720 goldens byte-identical.

## Compatibility

- Engine and UI are promoted together in the vendored set; a port pins them by
  content as always. The rebuilt UI still accepts the historical path contract
  from older engines; the 1.2.16 engine speaks only the descriptor contract to
  the UI it ships with.
- Recipes, markers, terminal-result schema and exit codes are unchanged. As
  with every engine bump, an installed marker from an older version triggers a
  clean revalidation on the next run.
