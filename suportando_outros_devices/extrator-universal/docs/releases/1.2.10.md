# NXExtract 1.2.10

NXExtract 1.2.10 adds structured terminal observability without changing the
approved graphical interface, extraction order or transaction boundary. The
SDL/direct-framebuffer drawing source, 640x480 and 1280x720 goldens and all
four GLIBC 2.17 release UI artifacts remain byte-for-byte unchanged.

## Atomic terminal result

Every completed installation attempt publishes `nxextract-result.json` by an
fsynced temporary-file rename. The strict version-1 schema records the final
phase, success or error, a finite `NXE####` support code, recipe identity,
package ID, ABI, validated file/byte totals, critical payload-rule summaries
and relative paths to both logs.

The selected container is represented only by the finite kind
(`apk-set`, `bundle`, `companion` or `existing`) and a SHA-256 identity derived
from the validated plan. External filenames, URLs and source origins are not
included. The marker now seals the package and source kind so a source-free
fast validation emits the same sanitized identity. A simulated rename failure
proves that readers see the previous complete JSON rather than a partial new
document.

Successful full installation, marker fast validation and validated-data
adoption have distinct stable success codes. Recipe, source, plan, validation,
runtime, operating-system and unexpected failures map to stable classes while
keeping their sanitized terminal cause. An interrupted process never reuses a
stale result: the previous terminal document is durably removed at the start
of a new attempt.

## Compact and detailed logs

The normal recipe log now contains phase milestones, the first miss of each
class, a count of repetitions and the terminal cause. Per-file extraction and
hook stdout move to `nxextract-detail.log`. Explicit `--verbose-log` or
`NXEXTRACT_VERBOSE_LOG=1` mirrors the lossless detail into the normal log for a
diagnostic run.

A synthetic 2,000-file fixture proves the compact log is more than 100 times
smaller than its detailed counterpart, finishes inside a bounded host budget,
retains the first error and repetition count, and never suppresses the terminal
cause. The complete suite contains 72 Python cases plus runtime, pin, ELF and
pixel-identity gates.

## Preserved contracts

- Content, package, ABI and critical internal payload—not an external filename
  or a single container hash—still decide compatibility.
- UI readiness controls remain in an owner-private runtime directory, never on
  FAT/exFAT/FUSE game storage.
- Native Android flow, progress phases, stage validation, journal order,
  marker publication, recovery and rollback are unchanged.
- The public UI still requires a proven SDL or graphical fbdev frame; TTY/ASCII
  output cannot authorize extraction.
