# Door Kickers: Action Squad — AArch64 PortMaster port

English | [Português](#português)

## English

Native AArch64 compatibility port of the Android version of **Door Kickers:
Action Squad 1.2.4**. The owner's `libAndroidEntryPoint.so` runs directly on
Linux through its original NativeActivity lifecycle; there is no Android VM or
CPU emulation. Proprietary game data is never redistributed.

### Architecture and framework

The single visible launcher is generated by `nxbootstrap 0.6.8`, providing the
PortMaster hand-off, single-instance lock, early private diagnostics, NXExtract,
controller environment and supervised shutdown. The adapter supplies the
game-specific AArch64 loader, JNI/Bionic/NDK surface, EGL/GLES2, OpenSL ES,
NativeActivity lifecycle and input queue. `FRAMEWORK-PIN.json` records immutable
versions and SHA-256 pins for the complete framework snapshot.

NXExtract 1.2.6 finds the owner's APK independently of its filename, identifies
`com.khg.actionsquad`, selects only `arm64-v8a`, validates the engine and all 831
assets, then commits them transactionally. No ARMv7 binary is built or shipped.

### Solved problems

- Android `funopen()` is bridged losslessly to glibc `fopencookie()`.
- Unsupported uint32 element draws on Mali-450 use a checked, GPU-resident
  uint16 mirror instead of lying about `GL_OES_element_index_uint`.
- OpenAL/OpenSL and SDL share 44.1 kHz; buffer completion runs on a dedicated
  thread and avoids the old audio stall/click.
- JNI `GetDpi()` reports the proven 240 dpi runtime value, restoring the native
  HUD dimensions.
- The original touch-first splash/controller confirmations are delivered as
  narrow boot events; gameplay input remains native.
- Firmware providers are inherited first. After a real SDL window failure, the
  proven R36S layout permits one same-DSO EGL/GLES retry; nothing is globally
  forced for other CFWs.

### Physical support

- NextOS Mali-450 AArch64: title, menus, mission, gameplay, HUD, audio, controls
  and clean save/exit form the established baseline.
- R36S ArkOS/dArkOSRE, Mali-G31, AArch64: NXExtract, KMSDRM/GLES video, 44.1 kHz
  audio, controller, gameplay and clean save/exit physically verified on
  2026-08-14.

muOS, ROCKNIX and other PortMaster CFW paths use the capability-driven generated
launcher, but are not claimed as physically verified by this release candidate.

| Action | Controls |

| Navigate / move | D-pad or left stick |

### Installation, build and source

See [INSTALLATION.md](INSTALLATION.md) for the exact owner-data identity. Set
`ACTIONSQUAD_SDK` to an AArch64 SDL2/EGL/GLES2 development sysroot and run
`./build-glibc230.sh`. The release executable is `actionsquad-nextos` and its
current maximum requirement is `GLIBC_2.27`.

`src/` contains the loader and adapter; `project/` contains the nxgenerator and
NXExtract source manifests; `package/build-package.sh` creates the deterministic
private candidate ZIP. Code is GPL-3.0-only; see `LICENSE` and `NOTICE.md`.

## Português

Port nativo AArch64 da versão Android de **Door Kickers: Action Squad 1.2.4**.
A `libAndroidEntryPoint.so` do dono roda diretamente no Linux pelo lifecycle
NativeActivity original, sem VM Android ou emulação de CPU. Dados proprietários
do jogo nunca são redistribuídos.

### Arquitetura e framework

O único launcher visível foi gerado pelo `nxbootstrap 0.6.8`, com integração
PortMaster, trava de instância única, diagnóstico privado antes do log,
NXExtract, ambiente de controle e saída supervisionada. O adapter fornece o
loader AArch64 específico, JNI/Bionic/NDK, EGL/GLES2, OpenSL ES, lifecycle
NativeActivity e fila de input. `FRAMEWORK-PIN.json` fixa versões imutáveis e
SHA-256 do snapshot completo do framework.

O NXExtract 1.2.6 encontra o APK sem depender do nome, reconhece
`com.khg.actionsquad`, escolhe somente `arm64-v8a`, valida a engine e os 831
assets e publica tudo de forma transacional. Nenhum binário ARMv7 é criado ou
incluído.

### Problemas resolvidos

- `funopen()` do Android é ligado sem perda ao `fopencookie()` da glibc.
- Draws uint32 não suportados no Mali-450 usam espelho uint16 validado e
  residente na GPU, sem mentir sobre `GL_OES_element_index_uint`.
- OpenAL/OpenSL e SDL trabalham em 44,1 kHz; a conclusão de buffers usa thread
  dedicada e remove o travamento/estalo antigo.
- O JNI `GetDpi()` devolve os 240 dpi comprovados, restaurando a HUD nativa.
- As duas confirmações touch-first do boot são eventos estreitos; a gameplay
  continua com input nativo.
- Providers do firmware são herdados primeiro. Após uma falha SDL real, o
  layout R36S comprovado permite uma única tentativa com EGL/GLES na mesma DSO;
  nada é forçado globalmente nos outros CFWs.

### Suporte físico

- NextOS Mali-450 AArch64: título, menus, missão, gameplay, HUD, áudio, controles
  e save/saída limpa formam o baseline estabelecido.
- R36S ArkOS/dArkOSRE, Mali-G31, AArch64: NXExtract, vídeo KMSDRM/GLES, áudio
  44,1 kHz, controle, gameplay e save/saída limpa verificados fisicamente em
  14/08/2026.

muOS, ROCKNIX e outros caminhos PortMaster usam o launcher gerado por
capacidades, mas ainda não são declarados como fisicamente testados nesta RC.
