# Magic Rampage — AArch64 PortMaster port

English | [Português](#português)

## English

This repository contains the open-source Linux adapter for **Magic Rampage
7.8.2**. It runs the owner's original Android AArch64 game library through the
native lifecycle; the APK and proprietary libraries are never redistributed.

### Architecture and framework

The visible launcher is generated by `nxbootstrap 0.6.12` through
`nxgenerator 0.2.6`. It provides the
PortMaster hand-off, single-instance lock, safe logging, NXExtract invocation,
controller environment and supervised shutdown. The adapter keeps JNI,
lifecycle, GLES, SDL_mixer audio, input translation and persistence at the
game-specific boundary. `FRAMEWORK-PIN.json` records immutable versions and
SHA-256 pins for the complete NextOS framework snapshot.

After NXExtract has completed and the owner payload has passed its gate,
`nxsplash 0.1.1` displays the mandatory bilingual **RETRO ELITE** hand-off for
five seconds. It runs before the adapter, private Android libraries and native
game lifecycle, has no per-port skip switch, and fails closed if its pinned
binary is missing or altered.

NXExtract 1.2.7 searches `gamedata/` and the port directory, identifies the
package independently of its filename, selects only `arm64-v8a`, validates the
container bounds plus exact critical native payloads, and commits them
transactionally. Its pinned low-GLIBC bilingual UI uses SDL or the active
terminal and must attest visible output before source scanning; it cannot
silently disappear or die during setup. No ARMv7 binary is built or shipped.

### Physical support

The established playable baseline was physically verified from release 1.1.0
on 2026-08-14:

- NextOS, Mali-450, AArch64: native Mali/GLES 2.0 video and playable runtime.
- R36S ArkOS, Mali-G31, AArch64: KMSDRM/GLES 3.2 video and playable runtime.

On both families, NXExtract accepted the documented reference owner APK, the mandatory
five-second hand-off completed, and the original native lifecycle reached the
game runtime. Music/SFX, controller and gameplay remain covered by the
established playable baseline.

The adapter first preserves the firmware/PortMaster SDL provider selection. On
the proven R36S firmware only, a failed SDL window creation permits one narrow
retry with the real combined Mali EGL/GLES DSO; no video driver is forced
globally.

### Owner data and installation

See [INSTALLATION.md](INSTALLATION.md). The documented reference is the legally
owned Magic Rampage 7.8.2 APK for `com.asanteegames.magicrampage`, with exact
size and SHA-256. Compatible packaging variants are gated by package, ABI,
container bounds and exact critical payload hashes. Saves remain inside the
port's `user/` directories.

### Build

Set `MAGICRAMPAGE_SDK` to an AArch64 SDL2/SDL2_mixer/libzip development sysroot
and run `./build-glibc230.sh`. The Docker recipe uses a pinned Debian Buster
base; every produced Linux ELF must require at most `GLIBC_2.30`. The release
binary is named `magicrampage-nextos` and currently requires `GLIBC_2.17`.

### Source map and licenses

- `src/`: game adapter, loader, JNI, GLES, audio and controls.
- `project/`: nxgenerator and NXExtract source manifests.
- `magicrampage/`: generated runtime contract and public documentation.
- `build-glibc230.sh`: low-glibc AArch64 build.
- `package/build-package.sh`: deterministic public-quality release gates.

Project code is GPL-3.0-only. Framework-derived portions and their upstream
attributions are recorded in `NOTICE.md`; the game remains property of its
owner.

## Português

Este repositório contém o adapter Linux de código aberto para **Magic Rampage
7.8.2**. Ele executa a biblioteca Android AArch64 original do dono seguindo o
lifecycle nativo; o APK e as bibliotecas proprietárias nunca são redistribuídos.

### Arquitetura e framework

O launcher visível foi gerado pelo `nxbootstrap 0.6.12` por meio do
`nxgenerator 0.2.6`. Ele faz a integração
PortMaster, trava de instância única, log seguro, chamada do NXExtract, ambiente
de controles e encerramento supervisionado. JNI, lifecycle, GLES, áudio por
SDL_mixer, tradução dos controles e persistência ficam no adapter específico do
jogo. `FRAMEWORK-PIN.json` fixa versões imutáveis e SHA-256 do snapshot completo
do framework NextOS.

Depois de o NXExtract terminar e os dados do dono passarem pelo gate, o
`nxsplash 0.1.1` exibe por cinco segundos a transição bilíngue obrigatória
**RETRO ELITE**. Ela roda antes do adapter, das bibliotecas Android privadas e do
lifecycle nativo, não possui opção de remoção por port e falha de forma fechada
se o binário fixado estiver ausente ou adulterado.

O NXExtract 1.2.7 procura em `gamedata/` e na pasta do port, reconhece o pacote
sem depender do nome do arquivo, escolhe somente `arm64-v8a`, valida limites do
container e os payloads nativos críticos exatos e faz commit transacional. Sua
UI bilíngue pinada e de glibc baixa usa SDL ou o terminal ativo e precisa atestar
saída visível antes do scan; ela não pode sumir silenciosamente nem morrer
durante o setup. Nenhum binário ARMv7 é criado ou incluído.

### Suporte físico

O baseline jogável estabelecido foi verificado fisicamente na release 1.1.0 em
14/08/2026:

- NextOS, Mali-450, AArch64: vídeo Mali/GLES 2.0 nativo e runtime jogável.
- R36S ArkOS, Mali-G31, AArch64: vídeo KMSDRM/GLES 3.2 e runtime jogável.

Nas duas famílias, o NXExtract aceitou o APK de referência documentado, a transição
obrigatória de cinco segundos terminou e o lifecycle nativo original chegou ao
runtime do jogo. Música/efeitos, controle e gameplay continuam cobertos pelo
baseline jogável estabelecido.

O adapter preserva primeiro a escolha SDL do firmware/PortMaster. Somente no
firmware R36S comprovado, uma falha real ao criar a janela permite uma única
tentativa estreita com a DSO Mali que fornece EGL e GLES juntas; nenhum driver
de vídeo é forçado globalmente.
